# Создание параллельных окружений с разными версиями Python (macOS)

Когда вам нужно иметь рядом несколько окружений под разные версии интерпретатора, папки окружений называют по-разному (например, `.venv311` и `.venv310`). 

Папка `.venv` — это просто директория на диске. Чтобы они существовали параллельно, достаточно указать другое имя при вызове `python -m venv <имя_папки>`.

---

## 1. Установка версии 3.10 (если еще не установлена)

Проверьте доступность версии и установите актуальный релиз Python 3.10:

```bash
# Посмотреть точные доступные версии 3.10
pyenv install --list | grep " 3.10"

# Установить конкретную версию (например, 3.10.14)
pyenv install 3.10.14
```

---

## 2. Создание окружений рядом в одной папке проекта

### Шаг А: Окружение для Python 3.11
```bash
# 1. Выбираем версию 3.11 для текущей сессии терминала
pyenv shell 3.11.8

# 2. Создаем окружение с говорящим именем
python -m venv .venv311
```

### Шаг Б: Окружение для Python 3.10
```bash
# 1. Переключаем текущую сессию терминала на 3.10
pyenv shell 3.10.14

# 2. Создаем второе окружение рядом с первым
python -m venv .venv310
```

После этого в директории проекта появятся две независимые папки:
```text
my-project/
├── .venv311/     # Python 3.11.8
├── .venv310/     # Python 3.10.14
└── main.py
```

---

## 3. Переключение между окружениями

Для работы с нужной версией достаточно активировать соответствующий скрипт:

### Работа в Python 3.11:
```bash
source .venv311/bin/activate
python --version   # Выведет: Python 3.11.8
# ... работа, установка пакетов через pip ...
deactivate
```

### Работа в Python 3.10:
```bash
source .venv310/bin/activate
python --version   # Выведет: Python 3.10.14
# ... работа, установка пакетов через pip ...
deactivate
```

> **Важно:** После того как виртуальное окружение создано, вызывать `pyenv shell` каждый раз уже **не нужно**. Внутри папки `.venv310/bin/` уже жестко зафиксирована ссылка на Python 3.10, а внутри `.venv311/bin/` — на Python 3.11. Достаточно просто выполнить `source <путь_к_папке>/bin/activate`.

---

## 4. Альтернатива: использование плагина `pyenv-virtualenv`

Если вы не хотите хранить папки `.venv*` прямо внутри каталога проекта, можно использовать плагин `pyenv-virtualenv`, который хранит окружения централизованно (по аналогии с Conda):

```bash
# Создание окружений
pyenv virtualenv 3.11.8 env311
pyenv virtualenv 3.10.14 env310

# Активация
pyenv activate env310
# или
pyenv activate env311
```
